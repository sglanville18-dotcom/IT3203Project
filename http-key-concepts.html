Core HTTP ideas worth remembering

This page focuses on the parts of HTTP that show up often when building, testing, or troubleshooting websites.

Status codes

These codes tell the client what happened after a request.

  • 200: the request worked
  • 301 / 302: the resource moved or redirected
  • 404: the requested page or resource was not found
  • 500: the server had an internal error

Headers

Headers carry extra information with the request or response. They can identify the content type, accepted data format, caching rules, authorization details, and more. They are one of the easiest ways to understand what is happening behind the page.

Stateless by design

HTTP does not automatically remember earlier requests. Each one is treated as separate unless extra tools are used. That is why websites use cookies, sessions, and tokens to remember that a user is logged in or has items in a cart.

HTTP and APIs

Many APIs use HTTP because it is already built around clear requests and responses. A client can send a GET request to read data or a POST request to submit it. This is one reason HTTP is not only for webpages. It is also a major part of app-to-app communication.

Common mix-ups

HTTP is not the internet itself

It is one protocol used on top of lower networking layers.

HTTPS is not a different website language

It is HTTP with encryption and certificate-based trust.

404 does not always mean the whole server is broken

It usually means that one requested resource could not be found.
