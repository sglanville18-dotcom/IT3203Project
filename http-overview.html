How HTTP works during a normal page load

This page focuses on the actual flow from clicking a link to seeing content in the browser.

The main job of HTTP

HTTP works at the application layer and is mainly used to move web-related information between a client and a server. In most everyday situations, the client is the browser and the server is the machine hosting the website or service. The browser sends a request for a resource, and the server returns a response that contains both data and metadata.

Page load walkthrough

  1. A user enters a URL or clicks a link.
  2. The browser identifies the resource it needs.
  3. An HTTP request is sent to the server.
  4. The server responds with a status code, headers, and content.
  5. The browser may send extra requests for CSS, JavaScript, images, or fonts.
  6. The page is assembled and displayed.

Methods you will keep seeing

Method What it usually does
GETReads or requests information
POSTSends new information to be processed
PUTReplaces or updates an existing resource
DELETERequests removal of a resource

What is inside the request?

A request commonly includes the method, the resource path, the protocol version, headers, and sometimes a message body.

What is inside the response?

A response usually includes a status code, headers, and the returned data such as HTML, JSON, an image, or a file.

One detail students usually miss

A single webpage is often not one request. It can be many requests. The main HTML file may load first, but then the browser asks for stylesheets, scripts, images, icons, and sometimes API data. That is part of why performance matters so much in modern HTTP versions.
